# 結果の読み方と報告の書き方

## 図の一覧 (`figures/` = 学習網, `figures_bs/` = コンセンサス網)

| 図 | 内容 |
| --- | --- |
| `01_structure_full.png` | 全体構造 (ノードサイズ=次数, 赤=注目遺伝子, ラベル=ハブ+注目遺伝子) |
| `02_importance_full_<metric>.png` | 全体構造。エッジの色・太さ = 重要度 |
| `03_importance_top_<metric>.png` | 重要度上位エッジの部分グラフ (全ノードにラベル) |
| `04_targets_highlight.png` | 注目遺伝子 (赤) と近傍 (緑)・関連エッジ (橙) |
| `05_target_ego_<metric>.png` | 注目遺伝子とその直接の親子のみ |
| `06_bootstrap_prob.png` | エッジのブートストラップ確率 (コンセンサス網のみ) |
| `subsets/subset_<label>_<metric>.png` | 群ごとの重要エッジ (背景に全体網を薄く) |
| `subsets/subsets_grid_<metric>.png` | 全群を共通レイアウトで並べた比較図 |
| `subsets/subsets_overlay_<metric>.png` | 全群を 1 枚に重ねた図 (色相=群, 濃さ=重要度) |
| `subsets/subsets_multichannel_<metric>.png` | 3 チャンネル統合 (+ 線の太さ=ブートストラップ確率) |
| `figures*/edge_importance_named_<metric>.tsv` | 重要度降順の名前付きエッジ表 |

`<metric>` は `dlogL` / `dBIC` / `dK2` / `dBDeu`。図を作るメトリクスは
`--metrics` (`VIZ_METRICS`) で絞る。全体図は 1 枚に情報を詰めすぎるので、
議論には `03_importance_top_*` と `05_target_ego_*` を使う。

## エッジ重要度 (`out/edge_importance.tsv`)

列: `u v ΔlogL ΔBIC ΔK2 ΔBDeu meanΔlogL_per_sample stdΔlogL_per_sample`。
そのエッジを 1 本除いたときのスコア変化。大きいほど説明力が高い。

* **ΔlogL はサンプル数に比例する。** 群別 (各 30 サンプル) の値は全サンプル版
  (120 サンプル) より必ず小さい。絶対値を群間で比べるのではなく、
  `meanΔlogL_per_sample` を見るか、群内での順位で比べる。
* `stdΔlogL_per_sample` が大きいエッジは、少数のサンプルが効いている
  (外れ値・サブポピュレーション) 可能性がある。
* ΔBIC は罰則込みなので、辺の必要性の判断には ΔlogL より保守的。

## ブートストラップ確率 (`out/integ_edges_score.tsv` の 4 列目)

リサンプル間で何割の学習に出てきたか。**構造の確信度はここで語る**、重要度では
語らない (重要度は「その構造を仮定したときの効き」)。

* 確率の標準誤差は `0.5/sqrt(B)` 以下。B が小さいと 0.3 と 0.5 の差に意味は無い
  (`parameter-sizing.md` の表)。
* 高確率エッジだけを残したコンセンサス網 (`out/integ_*`) が、ユーザに見せる
  「推定ネットワーク」の本体。学習網 (`out/edges.tsv`) は 1 回の探索結果にすぎない。
* **B が小さいとコンセンサス網は学習網より辺が増える。** 例: B=6 では
  「2 回以上出現 = 確率 0.33」を満たす辺が大量に通り、99 辺の学習網に対して
  191 辺のコンセンサス網ができる。所要時間の計測用に走らせた小さな B の結果を
  ネットワークとして解釈してはいけない。

## 向きの解釈 — 必ず添える注意

観測データだけでは、同じ独立性を表す DAG (マルコフ同値類) の向きを区別できない。
骨格 (無向グラフ) が正しくても向きは反転しがちで、実データの評価でも誤りの多くは
「向きが逆」になる。

したがって:

* **「A が B を制御する」と書かない。** 「A と B の間に依存関係があり、この構造では
  A → B と推定された」と書く。介入実験や時系列がない限り因果の向きは主張できない。
* 向きの議論をするなら、ブートストラップで逆向きエッジも数える
  (`bs/edges_seed*.tsv` に両向きが出ていれば向きは不定)。
* 既知の生物学的知識と向きが合わないことは、モデルの誤りではなく同値類の問題で
  あることが多い。

## 群 (条件) 別の比較

構造とカウント表を固定して評価データだけ差し替えているので、比較できるのは
「同じ構造の中でどのエッジがどの条件で効いているか」。**群ごとに別の構造を
学習しているわけではない。**

* 群間で `meanΔlogL_per_sample` の順位が入れ替わるエッジが、条件依存の候補。
* 群のサンプル数が小さいとノイズが支配する。`MIN_GROUP_SAMPLES` を上げて
  小さい群は落とす方が誠実。
* 図は `subsets_grid_*` (並置) と `subsets_overlay_*` (重ね) の両方を見る。

## HTML レポート (`report.html`)

図・重要度テーブル (上位 N)・データ要約を 1 枚に集約。存在する成果物のみ
取り込むので途中でも作れる。共有用に単一ファイルが必要なら `--embed`
(メトリクスを `--metrics` で絞ってから)。

## 報告に必ず含める項目

1. **データの前提**: N サンプル × D 変数、正規化と離散化 (`NORMALIZE`, `N_BINS`,
   `DISC_METHOD`)、フィルタで何遺伝子が落ちたか、注目遺伝子が残ったか。
2. **学習設定**: `SCORE` / `ESS` / `MAX_PARENTS` / `ITERS`、辺の本数、
   反復上限で打ち切られていないか。
3. **安定性**: 総リサンプル数 B、`THRESHOLD_PROB`、コンセンサス網の辺の本数、
   確率の標準誤差。
4. **主要な所見**: 上位エッジとハブ、注目遺伝子の近傍、群間差。
5. **限界**: 向きの不確かさ (マルコフ同値)、サンプル数に対する P_eff の制約、
   落とした遺伝子のエッジは検出不可能であること。

## 指標が伸びないときに疑う順番

サンプル数・離散化・スコア設定を先に疑い、探索 (`ITERS`) は最後。
情報が乏しい設定では**真の構造がスコア最大にならない**ことがある
(`example_bulk` では学習網の BDeu が真の構造より高く出る)。この領域では
探索が完璧でも正解には戻らないので、`ITERS` を増やしても無駄。

判定手順:

1. `P_eff = floor(log_r(N/10))` を計算する。1 未満なら離散化かサンプル数の問題。
2. `out/log_learn.txt` が反復上限で切れていないか確認する (切れていれば `ITERS`)。
3. 正解構造が手元にあるなら、その構造のスコアを `--iters 0 --init <true edges>`
   で計算し、学習網のスコアと比べる。学習網の方が高ければ探索の問題ではない。

# パラメータの決め方 (D, N, r からの導出)

記号: **D** = 変数数 (遺伝子数)、**N** = サンプル数、**r** = 1 変数の状態数
(= `N_BINS`)、**P** = `MAX_PARENTS`。

## 1. 実効的な親の数 P_eff — すべての起点

親を P 個持つノードの CPT は `r^P` 通りの親設定を持つ。1 設定あたり 10 サンプル
程度ないと罰則付きスコア (BIC/BDeu) はその親を保持しない。したがって

```
P_eff = min(MAX_PARENTS, floor(log_r(N / 10)))
```

* N=120, r=3 → `floor(log_3 12)` = 2 → 親 3 個は保持されない。
* N=120, r=2 → `floor(log_2 12)` = 3 → 親 3 個まで保持される。
* **P_eff < 1 になる (N < 10·r) なら、その離散化ではネットワークを学習できない。**
  `N_BINS` を下げる、サンプルを増やす、変数を絞る、のいずれかが必要。

`MAX_PARENTS` は P_eff より大きくしても意味が無く、探索を遅くしメモリを食うだけ。
実用的には 2〜3。

## 2. `N_BINS` の選び方

N が小さいほど小さく。r を上げると表現力は増えるが `r^P` でデータが薄まる。

| N (サンプル数) | 推奨 `N_BINS` | 備考 |
| --- | --- | --- |
| < 30 | 2 | 3 値は無理。変数も 100 程度に絞る |
| 30〜100 | 2〜3 | 2 値の方が親を多く保持できる |
| 100〜1000 | 3 | 既定 |
| > 1000 | 3 (必要なら 4) | 上げるならメモリを確認 |

メモリの主要因は `q_i × r_i` (`q_i` = 親の状態数の積)。`N_BINS` と `MAX_PARENTS`
がメモリ爆発の 2 つのつまみ。

## 3. `ITERS` / `ITERS_BS`

Hill-Climb は成長段階で 1 反復に 1 辺しか足せない。必要反復数の下限は学習される
辺の本数 `|E| ≤ D × P_eff`。成長後の修正 (REMOVE / REVERSE) と Tabu の脱出に
成長段階の 2 倍を見込む:

```
ITERS    = 3 × D × P_eff        # de novo 学習
ITERS_BS = 1 × D × P_eff        # ブートストラップ (warm start なので成長段階が不要)
```

例: D=60, r=3, N=120 → P_eff=2 → `ITERS=360`, `ITERS_BS=120`。
`example_bulk` の既定 (5000 / 1500) は必要量の 9 倍 / 8 倍で、余裕を持たせた値。

D が大きいと `ITERS` も比例して増え、1 反復のコストも |E| とともに増えるので
総時間は概ね `ITERS²` で伸びる。D が数千なら `ITERS_PER_VAR × D` の形で
自動スケールさせる (`example_dream/config.sh` と `iter_state.sh` が実例。
反復数で打ち切られたかを `budget_binding` として記録している)。

**反復数が足りているかの確認**。探索は必ず `ITERS` 回まで回る (改善が止まっても
delta=0 の REVERSE を続けるので `[stop]` はほとんど出ない)。したがって
「最後まで動いていた」ことは不足の証拠にならない。見るのは**最後に最良スコアが
更新された反復**で、判定用のツールがリポジトリにある:

```bash
"${FASTBN_HOME}/example_dream/iter_state.sh" out/log_learn.txt
#   -> 反復十分 (最良更新 it=163/600)      … このまま使える
#   -> **反復予算が律速** (最良更新 it=..)  … ITERS を倍にして再実行
# --flag を付けると 1 (律速) / 0 (十分) だけを返す (自動化用)
```

判定基準は「最後の 10% の反復でまだ最良スコアが更新されたか」。

## 4. ブートストラップ回数 `BOOTSTRAP × SEEDS`

エッジ出現確率 p の標準誤差は `sqrt(p(1-p)/B) ≤ 0.5/sqrt(B)` (B = 総リサンプル数)。

| B | SE の上限 | `THRESHOLD_PROB` 判定の幅 (±2SE) |
| --- | --- | --- |
| 50 | 0.071 | ±0.14 (粗い。傾向を見るだけ) |
| 100 | 0.050 | ±0.10 |
| 200 | 0.035 | ±0.07 (実用の下限) |
| 500 | 0.022 | ±0.045 |

`SEEDS` は並列プロセス数 (CPU コア数に合わせる。`MAX_JOBS` で同時実行を制限)、
`BOOTSTRAP` は 1 プロセス内の反復数。`B = BOOTSTRAP × SEEDS` が目標値になるよう
`SEEDS = min(コア数, 10)`, `BOOTSTRAP = ceil(B_target / SEEDS)` で割り振る。

**総実行時間 ≈ 学習 1 回の時間 × B / min(SEEDS, MAX_JOBS)。** 必ず
`BOOTSTRAP=3 SEEDS=2` で 1 回測ってから本番の B を決める。

`THRESHOLD_PROB` は 0.3 前後が実用的な出発点 (`THRESHOLD_COUNT` は最低出現回数)。
コンセンサスエッジが 0 件になったら閾値を下げるか B を増やす (スクリプトは
0 件で中断する)。

## 5. スコア関数 `SCORE`

| スコア | 使いどころ |
| --- | --- |
| `bdeu` (既定) | 一般用途。`ESS` (等価サンプルサイズ) が事前分布の強さ。N が小さいなら 1〜10 |
| `bic` | 疎な構造が欲しいとき、サンプルが多いとき。罰則が強い |
| `k2` | 比較用 |

エッジ重要度の評価スコア `SCORE_IMP` は学習スコアと別に指定できる (既定 `bic`)。
`--ess` は `bdeu` にしか効かない (他では警告が出る)。

迷ったら `SCORE` を変えて `RUNDIR` を分けて 2 通り走らせ、コンセンサス網の
辺の本数と安定性で比べる。

## 6. 候補親の事前選択 (D が大きいとき)

`TOPK` (上位 K の候補親のみ試す) / `CAND_METRIC` (mi | chi2) /
`MI_SAMPLE` (MI 計算に使う行のサブサンプル) / `MI_BUDGET` (テストする相手の上限)。

D が数千以上では MI 事前選択そのものが重い (コストは `遺伝子数 × mi-budget ×
サンプル数`)。`TOPK=20` 程度で始め、`REACH=lazy` (既定) を維持する
(`dense` は `D²/64` ワードのビットセットを持つので 10⁴ ノード超では重すぎる)。
